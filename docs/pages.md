# Page tree — what each page does

> Moved verbatim from `CLAUDE.md` on 2026-09-05.

23 pages (22 in the nav plus `/cameras/bindings`), all server components by default; client components are scoped to interactive bits (forms, auto-refresh). The sidebar ([`Nav.tsx`](src/components/Nav.tsx)) groups them into four labeled sections — **Live** (Overview / Topology / Incidents / Cameras), **AI & Storage** (Search / Ask the Store / VSS Chat / Evidence / Storage / KV Cache), **Configure** (Scenarios / VLM Prompt / Tuning / Agent / Test Footage / Profiles), **System** (Secrets / Logs / Diagnostics / Sizing Studio / Settings / About); section headers are hidden in kiosk mode. Below the groups, an **AI Factory** link opens the AI Factory UI (`AI_FACTORY_URL`, no link when unset) in a new tab, in every box mode — it is rendered outside `NAV_GROUPS` because it is not a console page, and the ISV-ARCH-05 generator reads `NAV_GROUPS` as the page list.

**Every page carries the box-mode banner** ([`BoxModeBanner.tsx`](src/components/BoxModeBanner.tsx), rendered by `Shell`): while the AI Factory's GPU switch has the box in a mode other than `vss`, a strip reads "VSS paused — the box is running the LLM (AI Factory)" with a link to the AI Factory; in kiosk mode it is a full-screen notice (Exit kiosk stays on top). It polls `GET /api/box-mode` every 10 s and renders nothing until the first answer or when the mode is `vss`. What the console holds back meanwhile: README, "Sharing the box with the AI Factory".

| `/` | **Two views.** Operator (normal) mode: Overview KPIs (cluster baseline, pod summaries, NIM health, GPUs, Kafka topic depth). **Kiosk mode (`?mode=kiosk`)** renders the showroom **story hero** ([`KioskHero.tsx`](src/components/overview/KioskHero.tsx)) instead — Cameras watched → Incidents detected → Stored on ARTESCA (on-prem) → NVIDIA compute, a clean health verdict, and a latest-incidents peek — with no cluster plumbing (Kafka/namespaces/Grafana creds). The hero's incident totals + newest incidents come from [`collectHeroExtras()`](src/lib/hero-collector.ts) (caption `/stats` + alert-bridge backlog, fail-soft); everything else reuses the overview snapshot; both auto-refresh via `OverviewAutoRefresh`. Auto-refreshes every 5s via `OverviewAutoRefresh` (client) → `/api/status/overview`. A **reachability strip** (`ConnectivityStrip` → `/api/diagnostics/connectivity`, polled every 5s) shows per-backend console→cluster reachability — K8s API, Prometheus, camera-sim (mediamtx), Kafka, **playback (VST storage)** — fetches back one minute that VST's own `/storage/timelines` lists, so a VST storage manager that failed to initialize at process start (every `/storage/file` read 500 `VMSInternalError` while recording continues, showroom 2026-09-10) reads red here instead of only in a log that rotates — S3, and the **alert-bridge incidents source** (`GET /api/v1/realtime/incidents`, the path the Incidents page depends on); each probe is independent and fail-soft. **GPU Util (2m avg)** headlines the **busiest** card, named by index (e.g. "GPU 0 · 47%"), with every card's value in the sub-line — an average across cards would read a saturated card as comfortable headroom next to one idle by design ([`busiestGpuHeadline()`](src/lib/gpu-kpi.ts), same per-card helpers `/tuning`'s Stream Density card uses). The GPUs section surfaces a **Grafana access card** (URL + user + password in clear) linking to ARTESCA's `:8443` Grafana for historical GPU graphs — shown only when `CLUSTER.grafana.url` is set; the password cell names why it's blank (e.g. "GRAFANA_PASSWORD unset") instead of a bare dash when `CLUSTER.grafana.password` isn't configured — the console never reads the ARTESCA Keycloak admin secret itself (`console-reader` carries no `secrets` verb), so an in-cluster deploy that hasn't set `GRAFANA_PASSWORD` at deploy time is always the reason, not a probe result. The GPU-sharing card's **Remote models panel** ([`GpuSharingCard.tsx`](src/components/overview/GpuSharingCard.tsx) → `collectGpuAllocation`/`resolveRemoteModels` in [`src/lib/gpu-allocation.ts`](src/lib/gpu-allocation.ts)) reads the live vss-agent env (`LLM_BASE_URL`/`LLM_NAME`) and, for any off-cluster endpoint, shows the effective **API base** (`{LLM_BASE_URL}/v1` — an API endpoint, not a web page; the bare host 404s in a browser) plus a **live health badge** from a cached (60s) probe of `{base}/v1/models` using the agent's key: `● reachable` / `✕ URL misconfigured` (HTTP 404 — a trailing `/v1` → `/v1/v1`) / `✕ auth failed` / `▲ unreachable`. This makes an `LLM_BASE_URL` misconfig visible instead of a silent chat failure. |
| `/topology` | Single-frame path diagram (camera-sim → VST → RTVI VLM → Agent → S3) with per-component health pulled from `/api/pods`. A node's Restart action (`POST /api/restart/<component>`) answers 409 for the VLM and the VST recorder while the box is not in `vss` mode. |
| `/incidents` | Incident timeline — live via SSE (`/api/incidents/live`, [`useIncidentStream`](src/app/incidents/use-incident-stream.ts)) layered over a plain-`GET` backlog, with exponential-backoff reconnect and a 10s-polling fallback once SSE gives up. **Filters** ([`IncidentsFilters`](src/components/incidents/IncidentsFilters.tsx) + [`MultiSelectDropdown`](src/components/incidents/MultiSelectDropdown.tsx)): time-window + severity buttons, plus **sensor** and **scenario multi-select dropdowns** — persisted to `localStorage["console:incidents:filters:v1"]` (hydrated after mount so SSR + first client render both start from `DEFAULT_FILTERS`, no hydration mismatch). Sensor options are the distinct `sensorId`s in the loaded incidents; a selected value that's no longer in view stays listed so a persisted pick is always de-selectable. Visible in **kiosk mode** at `?mode=kiosk` (full-screen, no chrome — for the showroom display). **Generate Report** (per-incident, in the [`IncidentDetail`](src/components/incidents/IncidentDetail.tsx) dialog): `POST /api/incidents/report` → [`generateIncidentReport()`](src/lib/incident-report.ts) feeds the incident's VLM reasoning (`raw.info.reasoningDescription` + `summary`) + metadata + extracted clip frames to the live agent LLM (Claude/Nemotron, resolved from the same `LLM_BASE_URL`/`LLM_NAME` the agent uses) and renders a structured markdown report — Overview / Location / Involved parties & vehicles / Timeline / Evidence — via the shared [`MarkdownReport`](src/components/MarkdownReport.tsx) renderer. The Evidence section (frame stills via `/api/clips/<sensor>/<ts>/thumb` + clip link) is appended deterministically so it always renders; an LLM failure degrades fail-soft to a deterministic report + `warnings[]`, never a 502. Reports persist keyed by `{sensorId, ts}` (no stable incident id) in SQLite `incident_reports` and re-open on mount via `GET /api/incidents/report?sensorId=&ts=` with a Regenerate (`force:true`) affordance. |
| `/chat` | Conversational chat with the vss-agent (`POST /api/chat` → the agent's OpenAI-compatible `/chat`). Replies render as markdown via the shared [`MarkdownReport`](src/components/MarkdownReport.tsx) renderer (`react-markdown` + `remark-gfm`, also reused by the incidents Generate Report action); a reply link ending in `.mp4`/`.webm`/`.mov` renders as an inline `<video>` (clip/snapshot media URLs are rewritten server-side to the same-origin `/api/media` proxy). A camera-scope selector restricts a query to one registered camera; a **G4a probe** button fires a fixed probe query and flags an empty or canned-failure response. History persists to `localStorage`. **Archive-search routing:** `/api/chat` detects search intent ("find every…", "show me all…", "search the footage…", `search:`/`find:` prefixes) via [`chat-search-routing.ts`](src/lib/chat-search-routing.ts) and answers from the caption-indexer (`/search`) instead of the agent — the closed vss-agent has no `video_search` tool — returning the same ChatCompletion shape so thumbnails render inline, each linking to `/search?q=`. Ordinary questions still go to the agent. Disable with `VSS_CHAT_SEARCH_ROUTING=0`. **Voice:** STT + TTS via [`use-voice.ts`](src/lib/use-voice.ts). A **Voice selector** picks the TTS engine — browser Web Speech voices (default "auto" pins `en-US` + best English voice; the raw system default mangled English on a non-US host) **or** on-box **NVIDIA Magpie TTS NIM** voices (via `/api/tts`), persisted; any NIM failure falls back to the browser voice. On-box voices are listed from `/api/tts/voices` (scoped to EN-US, "Speaker · Style" labels). |
| `/search` | Semantic search over the VLM caption archive. `POST /api/search` proxies the vss-caption-indexer worker (`CLUSTER.search.url`, env `VSS_SEARCH_URL`) which embeds incident captions into Qdrant; results are clip-thumbnail cards (score chip, camera, category, age, one-line summary) with a clip-playback detail dialog (Summary + full description). `?q=` deep-links pre-fill + auto-run the search (used by the chat thumbnails). Each card shows `displayCaption()` — the worker's terse LLM `summary` (`meta/llama-3.1-8b-instruct` via `integrate.api.nvidia.com`, off the live VLM GPU; extractive fallback), falling back to `cleanCaption()` ([`search-caption.ts`](src/lib/search-caption.ts)) of the raw caption on older un-summarized points. Worker manifests: [`k8s/nvidia-vss/search/`](isv-labs:k8s/nvidia-vss/search/); build/sideload: [`scripts/build-search-worker-image.sh`](isv-labs:scripts/build-search-worker-image.sh); the summarizer needs secret `vss-caption-indexer-llm/NVIDIA_API_KEY` (nvapi- key). |
| `/storage` | Live "ARTESCA S3 — the AI's on-prem memory" panel: per-bucket object counts + bytes + 24h-written + a "latest objects landing" stream across recordings/incident-clips/agent-corpus, a capacity bar, and a "since you opened this view" growth counter. `GET /api/storage/substrate` → `collectStorageSubstrate()` ([`storage-substrate.ts`](src/lib/storage-substrate.ts), 30s cache, fail-soft) over `s3SubstrateStats` ([`aws.ts`](src/lib/aws.ts)). Auto-refreshes. Each bucket card also shows its lifecycle expiry, Object Lock status, its `AbortIncompleteMultipartUpload` rule (absent → a warning, same treatment an absent expiry gets), and its live count of incomplete multipart uploads (`ListMultipartUploadsCommand`, paginated and capped at 10,000, reporting `truncated` beyond that) — regression detection for the 2026-09-10 pyramid-showroom incident, where the recordings bucket carried 5,664 stale multipart uploads with no rule to clear them, aborted by hand. The ARTESCA card also states whether deletes are returning space — `reclamation idle / working / stuck / unknown` from hyperdrive's reclaimable-bytes gauge, relocation queue and hourly heartbeat on the metalk8s-monitoring Prometheus (`src/lib/helpers/artesca-reclamation.ts`); cluster-wide only, and an absent series renders unknown, never zero. The recordings totals come from one paginated walk of the whole bucket (up to 1,000 pages of 1,000 keys, [`bucket-scan.ts`](src/lib/storage/bucket-scan.ts)), shared with the Overview KPI card, the kiosk storage tile, the topology S3 node and the `/diagnostics` storage panel: a walk that stops at the cap is shown as a floor (`≥`), and one that has not finished yet as "counting", never as 0. |
| `/kvcache` | KV-cache offload telemetry — the model and endpoint in use, the offload bucket's object count and bytes, any warnings, and live cost timings. Polls `GET /api/kvcache` every 5s (`KvcacheSnapshot` in [`kvcache.ts`](src/lib/kvcache.ts)); the page mirrors the response shape locally rather than importing from the server-only collector, matching the convention `storage/page.tsx` uses. |
| `/analytics` | "Ask the store" analytics over the incident archive: a plain-English question box ([`store-questions.ts`](src/lib/store-questions.ts) rule-based → category/camera/window) answered with counts + a link to the clips, plus a dashboard (total, by-category/by-camera bars, by-day trend, window selector). `GET /api/analytics?hours=` → caption-indexer worker `/stats` (Qdrant scroll). |
| `/evidence` | **Immutable evidence via ARTESCA S3 Object Lock (WORM).** Seal an incident's clip into an Object-Lock bucket with retention, then **prove immutability** (attempt version-delete → ARTESCA denies, AccessDenied) + play the clip. `lib/evidence.ts` (ensure lock bucket, seal, list, verify) + `POST /api/evidence`, `POST /api/evidence/verify`, `GET /api/evidence`. Per-scenario option: `immutable` (enabled + retentionDays + mode) on the Scenario schema + a `/scenarios` toggle; `/evidence` prefills retention/mode from the picked incident's scenario. Verified on ARTESCA 4.3 (create-lock-bucket + put-with-retention + version-delete-denied). Auto-seal-on-new (reconcile) is a planned follow-up. |
| `/agent` | Unified agent page — one persistent header bar (live LLM health badge `● reachable` / `✕ URL misconfigured` / `✕ auth failed` / `▲ unreachable` from a `{LLM_BASE_URL}/v1/models` probe, an agent-reachability chip from the `vss-agent` `/health` probe, and a **Save + Restart** action) plus two tabs. **Configuration** tab: view **and edit** the live vss-agent routing config — system prompt, and a **Model preset** selector (*Nemotron Super 49B (NVIDIA)* · *Claude Opus 4.8 (OpenRouter)* · *Claude Sonnet 5 (OpenRouter)* · *Custom*) that switches the reasoning LLM **including provider** (`LLM_MODEL_TYPE` `nim`↔`openai`). A Claude preset points the agent at OpenRouter's OpenAI-compatible endpoint (`openrouter.ai/api`, vendor-prefixed model ids such as `anthropic/claude-sonnet-5`); the server wires the OpenRouter key itself (a `secretKeyRef` to the `vss-agent-anthropic` secret, never sent to the browser) and strips the `temperature` Claude 4.6+ models reject on that endpoint. `max_iterations` (the langgraph recursion guardrail) is **not** an operator-editable field here — it's a backend-managed default (25, floor) enforced durably by the Helm overlay patch job ([`k8s/nvidia-vss-helm-overlay/60-agent-config-patch-job.yaml`](isv-labs:k8s/nvidia-vss-helm-overlay/60-agent-config-patch-job.yaml), Fix 4); the `PATCH /api/agent-config` contract still accepts it as an optional field, unused by this page. **Save + Restart** writes via `PATCH /api/agent-config` — patches the `vss-agent-config` ConfigMap (prompt; plus, for a Claude switch, drops `temperature` from the `openai_llm` profile) and the `vss-agent` Deployment env (`LLM_MODEL_TYPE` / `LLM_BASE_URL` / `LLM_NAME`, and `OPENAI_API_KEY` via `secretKeyRef` for the `openai` provider) — the env write is a JSON-patch **replace** of the whole env array (a strategic merge would leave the stale plaintext `OPENAI_API_KEY` `value` alongside the `valueFrom` and 422) — then rolls the Deployment. Warns without blocking on a trailing `/v1` in the base URL — the agent appends `/v1` itself, doubling to `/v1/v1` and 404ing every query. **Tools** tab: the agent's tool catalog (hand-curated, not a live introspection), grouped by kind with per-tool purpose + example queries. `/capabilities` (the former standalone tool-catalog page) permanently redirects here (`next.config.js` `redirects()`). |
| `/cameras` | Camera registration UI. Writes to `pyramid-ingress` ConfigMap `cameras` + GCS canonical at `gs://scality-isv-labs-config/cameras/<vss-instance>.json`. |
| `/cameras/bindings` | Which scenarios each camera is bound to — the only page not in the nav; reached from `/cameras`. Reads `/api/cameras` + `/api/scenarios` and validates both with zod before rendering. |
| `/scenarios` | Alert-keyword scenarios. ConfigMap `scenarios` in ns `alerts`; GCS canonical at `scenarios/<vss-instance>.json`. |
| `/prompt` | VLM system prompt + model deployment-name swap. Writes to ConfigMap `rtvi-runtime-env`. While the box is not in `vss` mode the prompt is saved to the config store and not written to the VLM (the save answers 200 with a warning saying so); the reconcile loop applies it on its first pass after the box is back in `vss`. |
| `/tuning` | Knobs for VST (recording sink), alerts (cooldown, slack-configured), and the VLM inference path — 7 knobs split across ConfigMap (`max_num_seqs`, `kv_cache_percent`, `max_model_len`, `NIM_MODEL_PROFILE`) and the `rtvi-vlm` Deployment env (`NIM_DISABLE_CUDA_GRAPH`, `VLLM_NUM_SCHEDULER_STEPS`, `VLLM_MAX_NUM_BATCHED_TOKENS`). Save+Restart atomically patches both surfaces and rolls the NIM workload + rtvi-vlm Deployment. ⚠ While the AI Factory has the box in another GPU mode, the VLM and VST saves answer 409 before their first write — the workloads they roll are the ones the switch scales; alert cooldown and frame sampling still save. The two "advanced" sections (Inference engine, Speculative decoding) are collapsed by default — operator-facing explanations + recommended configs live in [`isv-labs:docs/vss-performance-tuning.md`](isv-labs:docs/vss-performance-tuning.md). **On the alerts/helm profile the surfaces differ** ([`cluster-refs.ts`](src/lib/cluster-refs.ts) + the tuning routes): there is no separate NIM workload/ConfigMap — NIM tuning reads/writes the `vss-rtvi-vlm` Deployment env (`VLM_BATCH_SIZE`, `VLLM_GPU_MEMORY_UTILIZATION`); **alert cooldown is per-scenario `cooldown_seconds` in the `scenarios` config store (reconciled to the CM), NOT a global env** — a CM-only write is reverted by the reconciler, so the route writes the config store; and **VLM frame sampling** lives in the `realtime-alert-rules` CM (top-level `num_frames_per_second_or_fixed_frames_chunk`), applied by re-registering each live alert rule. **The Stream Density / Headroom card** on this page reads the VLM's own metrics, scraped from `/v1/metrics` on port 8000 (`/metrics` 404s) — the histogram is `vlm_latency_seconds`, not `nim_*`. **The verdict is P95 latency as a fraction of the chunk duration** (tight past 50 %, behind real time past 80 %) plus the stream shortfall (`active_live_streams` minus the implied `req/s × chunk` count); NVIDIA's HPA figure — the fraction of requests over 1 s off the `le="1.0"` bucket, scale at ≥ 40 % — is shown but not judged, because it reads "behind real time" only for a chunk of about a second: at the showroom's 30 s chunk every request is over 1 s while P95 8.75 s uses 29 % of the chunk. Tokens/sec is `vlm_output_tokens_per_chunk_tokens`, and "Streams the VLM sees" is the `active_live_streams` gauge, shown beside the modelled `req/s × chunk duration` so a gap between the two is visible. ⚠ **GPU figures are per card.** `DCGM_FI_DEV_GPU_UTIL` returns one sample per `gpu` label; the headline is the **busiest** card and names its index, with a per-card row beneath it on a multi-GPU node — reading whichever sample came back first reported the idle card (0 %) while the VLM saturated the other (92 %). |
| `/test-footage` | **Replay a local video file through the real pipeline** to test the VLM prompt and alert scenarios on actual frames. Upload streams to the `test-footage-data` PVC ([`k8s/30-test-footage.yaml`](k8s/30-test-footage.yaml), mounted at `/footage` in both the console and a `test-footage-server` pod running mediamtx). mediamtx serves two REGEX paths and starts an ffmpeg **on demand** — `loop/<file>` (`-stream_loop -1`, for prompt iteration) and `once/<file>` (one pass) — so "start a run" is only registering a VST camera at that URL, and there is no process to supervise. A run reuses [`registerSensorAndArm`](src/lib/helpers/vst-register.ts) + `setIngestion`, so it exercises the same code path a real camera does. A **Scenario picker** chooses which alert profile the clip is judged against — `listAlertProfiles()` reads the distinct `alert_type` + `prompt` pairs off the live cameras in `realtime-alert-rules`, and the choice is passed through `setIngestion`'s `IngestionOverride`. This matters because scenarios are keyword filters applied to a caption *after* the VLM speaks: what decides whether a theft is described at all is the alert_type + prompt, so a run left on the default `general-activity` ("anything notable") proves the pipeline runs but tests no prompt and no alert rule. `pauseLive` stops the live cameras' **analysis** (never their recording) for the duration, which is what makes a prompt comparison repeatable on a GPU five cameras already saturate; a failed start restores them before surfacing the error. Test cameras are named `test-<stem>` so they are obvious in the camera list, incidents and scenario filters. **Abandoned-run recovery:** a run interrupted before it stops (tab closed, pod restarted) leaves the live cameras paused and nothing analysing; `pausedSensors()` surfaces that as a red repair banner, and Stop resumes the union of the caller's list and the ConfigMap marker — so the fix does not depend on the tab that started the run still existing. **One writer owns rule creation:** where `vlm-stream-reconciler` is deployed, clearing the paused marker *is* the resume — the console does not also create the rules. Doing both raced (neither writer sees the other's create in time on the eventually-consistent rule index, so both post and the reconciler logs `deduped extra rule`), producing ~2 min of a wrong rule set after every stop. The console falls back to creating them directly only when no reconciler exists, where there is no second writer. ISVD-507. Lib: [`test-footage.ts`](src/lib/test-footage.ts) (sanitising, streamed upload) + [`test-footage-run.ts`](src/lib/test-footage-run.ts) (start/stop, profiles, paused marker). |
| `/profiles` | Operator-defined "scenes" — saved prompt + scenario + tuning bundles. Applying one (`PUT /api/profiles/<name>`) writes the VLM Deployment, so it answers 409 as a whole while the box is not in `vss` mode rather than land the scenarios without the prompt. |
| `/secrets` | View-only status of cluster secrets. `GET /api/secrets/<key>` returns exactly `{ key, configured, ageMs }` — a boolean and a rotation age, never a value and not a length; rotation is write-only. Reads each secret via the K8s API — the console SA needs `get secrets` in the **`console` namespace** (the `console-secrets` Role in [`k8s/01-rbac.yaml`](k8s/01-rbac.yaml)) and in the workload ns (the dynamic `console-writer` Role); without it every card falsely reads "not configured". The registry ([`src/app/api/secrets/[key]/route.ts`](src/app/api/secrets/[key]/route.ts)) maps each UI key to the real secret+field on the alerts/helm profile: `ngc-key`/`nvidia-api-key` → `ngc-api`/`NGC_API_KEY` (NOT `ngc-secret`, which is the image-pull secret); `console-auth-password` reads configured from `CONSOLE_PASSWORD` **or** the rotated `CONSOLE_PASSWORD_HASH` (`statusKeys`). |
| `/logs` | Pod log tail across namespaces (rtvi, vst, alerts, agent). |
| `/diagnostics` | Cluster-wide health probes (kubectl version, namespace status, pod restart counts, recent events). |
| `/sizing-studio` | Embeds the standalone `sizing-studio.html` static tool (served from `public/`) in an iframe — sizes cameras, light-rails, AKHET® servers, GPUs/AI systems, and ARTESCA storage for a store by surface area and use case. "Open full screen" opens the same page directly, outside the iframe. |
| `/settings` | Auth, NextAuth secret rotation, app version. |
| `/about` | Build info (git SHA, build date, Node/Next versions), the resolved service-endpoint table (Kafka, Redis, VST, mediamtx, Prometheus, object-store, NIM, alert-worker, GCS config bucket), documentation links, and health/inventory panels for both config-persistence backends — GCS (`gcsHealthCheck` + per-surface cameras/prompt/scenarios object existence) and the config store (`configStoreHealthCheck` + per-surface counts, naming which backend answered and flagging a selection that was inferred rather than set). |
